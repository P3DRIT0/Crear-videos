# Auditoría local · 24 de noviembre de 2026

El estudio HOME funciona en el equipo doméstico y se han corregido los fallos
descritos abajo. La auditoría cubre código, operación, persistencia, licencias,
controles de red, navegador y pruebas reales acotadas. No constituye una
certificación de seguridad ni aceptación de calidad audiovisual profesional.

repositorio. No hubo publicación, cuentas, servicios externos nuevos, nuevos

[ADR 009](adr/009-auditoria-local.md).

## Hallazgos corregidos

La prioridad indica el impacto potencial antes de corregirlo, dentro del uso
local y cooperativo previsto; no es una puntuación CVSS.

| Prioridad | Hallazgo | Corrección y evidencia |
|---|---|---|
| Alta | Un fallo al preparar la siguiente etapa podía marcar como fallida la última operación completada | Registro de preflight separado; prueba de referencia conservada tras fallo posterior |
| Alta | El cleanup de VRAM podía hacer perder un resultado válido o interferir con otro trabajo | Guardado SQL y blob antes del cleanup; comprobar cola/Ollama antes de liberar; pruebas de fallo inyectado y trabajo ajeno |
| Alta | El registro podía verificar un archivo mientras ComfyUI cargaba desde otra ruta | Rutas exactas de pesos, argumentos completos del runtime y textos de licencia fijados; rechazo de duplicados y extra_model_paths.yaml; pruebas de rutas y overrides |
| Alta | La pérdida del historial de ComfyUI impedía recoger una salida terminada | Recuperación mediante ID único, grafo persistido, metadata PNG/MP4 y referencia por hash; no reenvía inferencia. Rechaza ambigüedad, corrupción, grafos/referencias diferentes y archivos mayores de 16 MiB |
| Alta | Variables offline y clientes locales no impedían por sí solos todo HTTP externo de los proveedores | Política de sockets Python para Studio/ComfyUI y proxy local de denegación para Ollama. DNS/TCP/UDP y HTTP/CONNECT probados; petición real de descarga bloqueada, sin cambiar modelos |
| Media | Ollama podía competir con memoria todavía retenida por ComfyUI | Descarga solicitada y comprobación de memoria del runtime antes de generar guion; espera limitada a 30 s |
| Media | Una escritura interrumpida podía truncar el estado del lanzador; start/stop podían solaparse | Snapshot temporal con fsync y reemplazo atómico; candado de gestión y limpieza del temporal. Prueba de fallo de escritura conserva estado anterior |
| Media | Los controles del panel podían usar datos incompletos durante una carga | Controles desactivados y workspace inert durante carga; error visible con reintento. Latencia y error de transporte SIMULADOS comprobados en navegador sobre lectura del piloto real |
| Media | Reconectar SSE repetía todo el historial | Cursor de revisión en URL, Last-Event-ID prioritario y validación acotada; pruebas de cursor y cabecera |
| Baja | El cierre de la prueba de navegador podía dejar el hijo del venv Windows | Cierre del árbol del servidor propio y aislado; recorrido WORK repetido con éxito |

## Límites y siguiente trabajo

1. **Aceptación audiovisual humana:** revisar identidad, movimiento, narrativa y
   marca. El QC técnico no puntúa estética ni promete calidad Higgsfield.
2. **Desconexión física y corte completo del PC:** no probados. La nueva evidencia
   de recuperación usa un checkpoint reconstruido con medios auténticos; no se
   presenta como un apagado real. Si no hay salida íntegra ni historial, el
   resultado queda incierto y requiere actuación explícita.
3. **Alcance offline:** controles de aplicación, no sandbox del SO. Python usa
   sockets restringidos y Ollama proxy de denegación; no se garantiza interceptar
   cualquier librería nativa/subproceso o programa ajeno. Sin prueba física no se
   certifica aislamiento completo. Los servicios escuchan en loopback.
4. **Stack objetivo:** Next.js/TypeScript, FastAPI/SQLAlchemy/Alembic, Temporal y
   LangGraph siguen pendientes; el ejecutable actual usa HTML/JS, HTTP Python,
   SQLite y checkpoints propios. PostgreSQL integral, Vitest y build Next no se
   ejecutaron en esta auditoría. No se reescribe el producto dentro de este ajuste.
5. **Dependencias:** se comprobaron versiones fijadas y compatibilidad local;
   no se hizo escaneo completo de advisories/CVEs ni auditoría del código de todos
   los proveedores. No se actualizaron paquetes a ciegas.
6. **Capacidad:** RAM de 16 GB limita concurrencia y resolución. No se probaron
   720p, modelos 14B, carga simultánea de otros programas ni campaña Exyo real.
7. **Publicación:** continúa desactivada. Configurar una integración oficial y
   publicar requiere un encargo separado; no se crea ningún servicio externo.

Se puede continuar produciendo y revisando en local con el perfil medido.
